## Why v8 exists

F6 proved an allowlisted native C++ arithmetic executor can accurately apply three project-authored toy mechanisms; F7 proved the native MoolBase schema router can select the appropriate procedure on a tiny public synthetic corpus with unique typed field names, tying a non-database deterministic comparator. Those were important **software integration and enforcement** results, not learned or scientific intelligence.

This v8 experiment changes surface names and some declared units. The original question domain/procedure labels are not supplied to selectors. Every allowed relationship is **manually curated in \`aliases.json\`**, explicitly unverified and tied to one project-authored source family; alternative wording has not been independently learned from source data.

## Components and evidence chain

1. \`build_semantic.py\` generates a new seeded 120-trial authored corpus and **separate local gold file**; the primary selector process never loads gold. Trial IDs are opaque and shuffled.
2. \`semantic_baseline.py\` normalizes using the same explicit 44 alias records in Python (B1).
3. \`native_semantic.cpp\` stores 44 unverified alias nodes using **actual GrapheneDB**, closes/reopens, resolves by \`metadata_search("alias", …)\`, validates source/field/type/unit/collision policy, and writes canonical typed queries and native source node IDs (B2).
4. Both arms run the same original F7 schema matching policy (the v8 C++ selector changes only fixed count 108 -> 120), then the unchanged original F6 native calculation executor. B0 sees raw unnormalized data with the old exact-field matcher.
5. \`score_semantic.py\` loads the separate evaluator-only key **after** routes and executed outputs exist, checks original F3 oracle results and explicit refusals; preserves every individual result, zero new verified facts and clear \`NOT_RUN\` markings.

## Frozen methodology

72 renamed in-library questions from seed 20261021 (60 valid numeric, 12 invalid assumptions); 48 additional negative controls (12 unsupported units, 12 conflicting synonyms for one concept, 12 out-of-domain prompts, 12 cross-domain combined inputs).

Controlled examples of conversions:
- A toy continuous regulator in \`centistate\` units = input * 1/100 \`state_units\`.
- Inventory usage in \`items_per_week\` -> divide by 7 to recover \`items_per_day\`.
- Supply lead time in \`hours\` -> divide by 24 to recover \`days\`.

No arbitrary unit algebra or temperature affine offset is supported. Mismatched/unrecognised units, nonintegral canonical integer quantities, duplicate semantic roles and blended domains are rejected, never silently repaired.

**Important hard scientific limitations:** Same authored ontology and task generator are both visible in the repo, and multiple fields have distinctive typed signatures. High performance does NOT mean neural knowledge or real semantic understanding. B1 and B2 have the same authored ontology and deterministic matching rules. B2's unique value is real database persistence, validated provenance and inspectable native receipts; it is **not expected to outperform B1 on correctness**.
