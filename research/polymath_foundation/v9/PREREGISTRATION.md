# MOOL-POLYMATH-F9-001 — Two-gate preregistration

**Protocol-first commit, 19 October 2026.** Base: frozen v8 commit `9afb22f5386004e10c773d8fb36024aad861b121`. No changes to v1–v8 protocols, tasks, baseline receipts or EP-PROCESS scoring.

## Gate 1: Semantic grounding on an actual stronger model

**Primary test:** Run real Qwen2.5 **7B-Instruct-GGUF** on the exact same 24 original **project-authored, open, nonindependent** natural-language tasks as the v8 Qwen2.5 1.5B pilot, with no gold or mechanism IDs in the inference requests. Use official Qwen GGUF `qwen2.5-7b-instruct-q3_k_m.gguf` pinned Hugging Face repository revision `293ca9a10157b0e5fc5cb32af8b636a88bede891`, Apache-2.0. Lower Q3_K_M quantization is a resource/quality compromise and is not capacity-matched to v8's Q4_K_M.

**Frozen choices:** CPU-only pinned llama.cpp commit `ff5a23376725e5a889fa0bfb987b7541dc304da0`, temperature 0, seed 20261022, context 4096, maximum 384 output tokens, all 24 stateless requests. Download and record exact model SHA-256. Use explicit model-request instructions that show field-value serialization and one *synthetic* worked normalization example; do not show any test question, actual gold output, arithmetic answer, or hidden category label. Two inference runs: first structured extraction; optional old-prompt replication is NOT included (would double CPU cost). Model-change and prompt-change effects are therefore confounded. This tests **a practical enhanced 7B+prompt configuration against historical v8**, not pure model scaling.

The expected model JSON is either `{"status":"normalize","target":"...","target_unit":"...","inputs":"name=value@unit#integer;...", "reason":"..."}` or `{"status":"abstain","reason":"...","target":"","target_unit":"","inputs":""}`. All values/units must derive from question text; no inferential answer calculation in model. Use strict unchanged v8 `adapt()`, `prepare_routes.py`, native C++ v8 selector and unchanged native v6 calculator, and **unchanged v8 evaluator** `score_semantic.py`. No repair with gold. A malformed model response scores incorrect even on out-of-domain tests. Prespecified output: 24 raw model JSON responses, extraction exactness, 12-valid task accuracy, 6 assumption boundary, 6 unfamiliar/composite refusals, token/latency/parse-error counts, model hash and complete raw evidence. Keep artifact even if incomplete.

**What would be interesting:** any valid applied question completed, without losing safe rejection of genuinely out-of-scope or assumption-violating cases. This is an exploratory pilot with no statistical superiority threshold; expert-blind independent semantic generalization remains NOT_RUN.

## Gate 2: Actual native HypoKosh–DWM hypothesis opposition

Build a C++ instrument using real `GrapheneDB`, `CompleteHypoKoshRuntime::reason`, and original typed edges; no imitation of DWM through prompts or JSON labels. Three *project-authored synthetic* candidate explanations for a generic incident, e.g. stock-reconciliation discrepancy caused by inbound-delay vs stock-snapshot lag vs order-policy rule. Build three scenarios with the same candidates but controlled evidence updates (baseline hypothesis-only, contradictory hypothetical observations, and rescinded/alternative-support context). Since `GrapheneDB` has no `delete_edge`, implement evidence-stage graph datasets as **separate independently reopened database snapshots**, not as a false history or claim of a complete persistent change-capture cycle. All evidence nodes and edges remain `project_authored_synthetic` and `EdgeOrigin::Hypothetical`, with no independent empirical sources and no Verified/Observed claims.

For each snapshot execute three **actual** capability ablations using identical stored nodes/edges/query vector/signature: G0 evidence expansion (hypokosh=false,dwm=false); G1 HypoKosh only (hypokosh=true,dwm=false); G2 HypoKosh + DWM (both true), and `update_model_world=false`, maximum two recovery cycles. Record native `HypoKoshRuntimeResult` status and evidence edges, selected primary node, initial/final opposition scores, challenge flag, challenged targets, reopen nodes, recovery rounds, `receipt.opposition_executed`, `receipt.convergence_executed`, `receipt.dwm_capability_enabled`, `receipt.hypokosh_capability_enabled`, safety/provenance classification. Assert no audited `Verified` fact or ModelWorld write; never convert unverified synthetic observations into discovered truth.

**Gate 2 engineering acceptance:** 9 real runtime evaluations (=3 snapshots x3 ablations), all raw receipts persisted, explicitly show where opposition actually ran and whether outputs differ. Externally measured correct-cause ranking, empirical falsification, and real outcome feedback remain NOT_RUN; if opposition does not happen or nothing improves, report a negative/null outcome, not a "reasoning breakthrough." Recorded evidence of an invocation alone must not be called hypothesis discovery.

## Integrity, negative controls and scientific limits

- Source and corpus hashes sealed. Read-only prior foundation files. No claims of independent science, world-model training, background self-learning, AGI, or statistically significant improvement.
- Gate 1 and Gate 2 separate jobs and acceptance conditions; a passed compiler must not be counted as passed inference or reasoning evaluation.
- Negative checks: no gold in Gate 1 inference inputs, malformed model answers never repaired, synthetic Gate 2 sources never silently promoted, all ablations use the same input graph, all snapshots have distinct receipts.
- Any failure must result in explicit INCOMPLETE/FAILED with archived evidence. No changing model, thresholds or prompt after seeing results; new experiment ID needed for substantive retuning.
- Follow-on real polymath test requires licensed independently held-out expert cases, truly contrasting causal models, discriminating tests, and independently authenticated outcome feedback.
