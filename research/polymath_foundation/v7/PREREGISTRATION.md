# MOOL-POLYMATH-F7-001 — Protocol freeze: select a mechanism without supplied mechanism ID

**Protocol-first commit, 2026-10-18, before v7 implementation or scores.** Base is successful v6 commit `2b2cc90f2b8e752aed6bca8b5b2cd910ec86dcee`. Preserve F1–F6, model pilot results, and frozen EP-PROCESS studies.

## Research question and classification

Can actual native MoolBase storage, ontology/provenance contracts and **typed mechanism matching** select the correct previously authored procedure, or abstain, on a fixed set of unlabeled tasks? This is **procedural routing** and input-applicability verification, not learned polymath reasoning or autonomous research. The three procedure signatures are already published and distinct. The protocol deliberately distinguishes type-signature identification from analogical or scientific understanding.

**Independent blindness limitation:** all questions are generated by code in this same repo using a public seed and public rules. Their gold remains physically separate from the candidate file, and is never passed to the native selector, but they are NOT externally authored or scientifically blind.

## Frozen trial population

- **72 in-library tasks** from unchanged v3 generator, new `random.Random` seed `20261020`: 20 admissible plus four out-of-assumption cases for each of three domains. Assign randomized opaque question IDs and shuffle questions; neither domain, card ID nor mechanism ID goes to selector.
- **12 incompatible-unit distractors:** duplicate twelve *valid* questions (4/domain), replace a required unit with incompatible `credits` while keeping field/type intact; correct action = explicit abstention.
- **12 out-of-domain tasks:** project-authored questions about optics, astronomy, and acoustics, with unknown correctly typed variables and no matching procedures; correct action = explicit abstention.
- **12 cross-domain composite tasks:** combine two full valid field sets from different mechanisms (4 each pair), with misleading narrative mixing both domains. A mechanism chosen for only part of the inputs is wrong; correct action = explicit abstention.
- **Total 108 tasks, 60 valid numeric calculations, 48 abstentions** (12 original invalid assumptions and 36 adversarial negatives). No generated task reveals the gold mechanism, correct answer, or source card ID. The evaluator holds the mapping in a different file. Opaque IDs must not encode domain or original F3 IDs.
- The three reviewed v6 cards and typed native procedure manifest are held unchanged; v7 adds selection, not new mechanisms.

## Frozen routing arms

**B0 — lexical-only:** TF-IDF/unigram overlap between question description and three procedure descriptions; no access to required input field schemas. Must decline zero-overlap and tied top scores; may misroute lexical distractors.

**B1 — schema-only non-database:** compare typed parameter names, types, units and requested target against the same three procedure declarations. Accept when exactly one candidate matches at least `required_fields-1` supplied fields, has no extraneous input fields, and exact field units/types/target unit; otherwise decline. This is a strong deterministic baseline, **not a learned AI**.

**B2 — actual native MoolBase:** store the original v6 procedure metadata as unverified nodes, close/reopen real C++ `GrapheneDB`, discover via `metadata_search` and run the **same decision algorithm as B1** with strict source identity, version, provenance and no Verified claims. Store ranked candidates, denial reasons and native evidence-node receipts. A performance tie between B1 and B2 is expected; B2 should establish persistence/traceability, not higher scientific accuracy by construction.

Each arm's accepted task becomes an input to the **unchanged original v6 C++ executor**, which validates units/assumptions and applies the allowlisted procedure. Rejected tasks never receive a numeric answer. Scorer compares exact decisions and numeric values to original unchanged v3 oracle, without providing it to B0/B1/B2 selection. Any incorrect selection is scored wrong even if the calculator later returns a benign abstention.

## Safety and interpretation

- Declared units are categorical strings; no automatic conversion or dimensional algebra yet. Unit conversions, aliases and domain ambiguity are future tasks.
- Original v6 mechanisms are toy/project-authored/unverified, not scientifically validated.
- A domain-name match in text is not evidence; type-signature matching may solve this benchmark trivially.
- No LLM is invoked; HypoKosh/DWM not executed in F7, their real native execution was documented in F5. The `autonomous AI selection` requirement remains **NOT TESTED**.
- Corpus and evaluation design are not independent of implementers; blind held-out expert assessments are **NOT RUN**.
- Do not assume that high B2 accuracy proves any scientific knowledge or improved capabilities vs B1.
- No free-form eval, no arbitrary code/connector use, no Verified evidence promotion, no generic "Observed" ingestion. Reject malformed, unauthenticated, duplicated or conflicting procedure registries.
- All candidates get the same immutable manifest/task information. B0 intentionally does not use structured schema as its definition, so retrieval performance may not be comparable in input information.

## Acceptance (engineering only)

1. 108 deterministic opaque challenges; traceable source and hidden gold-file hash; no domain/target answer leaked via IDs.
2. Real native MoolBase persisted/reopened and supplied candidates from `GrapheneDB::metadata_search`; all stored provenance remains unverified.
3. Both B1 and B2 reject all out-of-domain, composite and poisoned-unit tasks. B2 agrees with B1 on all tasks; disagreement is a defect, not a competitive win.
4. Execute accepted candidates through unchanged F6 C++ executor. Exact decision, citation, typed unit and numerical-output grading; report 60 valid calculations, 48 safe-boundary/unknown cases, and failure/cost categories by arm.
5. Adversarial tests for forged Verified status, duplicate stored sources, malformed units, cross-domain composites and wrong mechanism choices. Keep actual failures in CI receipts.
6. All results reported even if performance is poor; no post-outcome tuning to reclassify trials.

**Research gate after F7:** independent third-party, rights-cleared hidden task descriptions that do not leak unique schemas; evaluate genuine model-selected mechanisms and alternative hypotheses under matched budgets with scientific counterexamples, units conversion and unknown-mechanism discovery. This is the test that could contribute to a polymath claim.
