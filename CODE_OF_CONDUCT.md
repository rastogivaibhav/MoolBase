# MoolBase Community Code of Conduct

## Our commitment

We want MoolBase to be a professional, welcoming place for engineers, researchers, users and contributors to exchange ideas, reproduce results, report failures and improve the system.

Participation should be respectful regardless of background, identity, experience level, employer, geography or technical viewpoint.

## Expected behaviour

Examples of constructive participation include:

- criticising ideas, implementations and evidence rather than people;
- sharing reproducible technical detail when making claims;
- welcoming good-faith questions and first-time contributors;
- acknowledging uncertainty, mistakes and negative results;
- respecting privacy, confidentiality and intellectual-property boundaries;
- keeping technical disagreements focused on evidence and engineering trade-offs.

## Unacceptable behaviour

The following are not acceptable in project spaces:

- harassment, threats, intimidation or discriminatory abuse;
- personal attacks, trolling or deliberately inflammatory behaviour;
- sexualised language or unwanted sexual attention;
- publishing another person's private information without permission;
- knowingly submitting confidential, proprietary or unlawfully copied material;
- repeated disruption after a maintainer has asked for behaviour to stop.

## Scope

This code applies to repository issues, pull requests, reviews, discussions and other spaces where someone is participating as a representative of the MoolBase project.

## Enforcement

Maintainers may edit or remove contributions, close or lock discussions, reject changes, or restrict participation when behaviour is inconsistent with this code.

When possible, moderation will be proportionate to the behaviour and will distinguish good-faith technical disagreement from harassment or abuse.

## Reporting

If a concern can be handled publicly and safely, raise it in the relevant issue or pull request.

For security vulnerabilities, use the process in [SECURITY.md](SECURITY.md) rather than a public issue.

For conduct concerns that should not be discussed publicly, contact the project maintainer through the contact methods available on the maintainer's GitHub profile. Do not include secrets, credentials, customer data or other sensitive material in a public report.

## Scientific disagreement is welcome

MoolBase explicitly invites falsification attempts, negative results and technical criticism. A result that contradicts a project claim is not a conduct problem when it is presented professionally and with reproducible evidence.

The standard is simple: challenge the claim, preserve the evidence, respect the people.
