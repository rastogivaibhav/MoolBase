WHERE THE IDEA STARTED

MoolBase did not begin as an AI memory product.

“I originally imagined a temporal database that could reason across facts from different sources, move through multiple rounds of convergence and divergence, and establish a new fact from that process.”

The starting problem was not simply retrieval. Real evidence arrives at different times, from sources with different lineage, confidence and independence. Some observations repeat the same origin. Some contradict one another. Some become stale. A database can preserve all of those records and still leave the hardest question unanswered:

What should be treated as the currently established fact — and why?

01

Time changes meaning

A fact that was reasonable at T₁ may become superseded at T₂. Temporal order and revision history are part of the evidence, not metadata to throw away.

02

Sources are not equal

Ten records can still represent one underlying source. MoolBase preserves provenance and evidence families so copied claims do not become artificial corroboration.

03

Convergence is not enough

A leading explanation can still be wrong. The system needs a deliberate divergent phase that preserves opposition and tests what could overturn the apparent winner.

04

Facts need a lifecycle

Observed, candidate, contested, established and superseded states should remain inspectable rather than collapsing into an opaque final answer.

HOW THE SYSTEM EVOLVED

Each layer appeared because the previous layer exposed another problem.

01

MOOLBASE CORE

Preserve the temporal evidence state.

Store observations, provenance, typed relationships, causal context, supersession and durable state so later reasoning has something trustworthy to work from.

02

HYPOKOSH

Keep competing possible facts alive.

Once several explanations can fit the same evidence, the system needs hypotheses rather than premature certainty. HypoKosh competes alternatives and allows convergence or abstention.

03

DWM / DIALECTIC ENGINE

Challenge the apparent winner.

Convergence can reinforce a weak conclusion. DWM introduces material opposition, bounded reopen and targeted re-expansion so a leading hypothesis must survive challenge before the process settles again.

A SIMPLE EXAMPLE

A normal database stores the records. MoolBase asks what they establish together.

Imagine multiple observations about an overheating machine. Two sensors agree, an alert is derived from one of them, and another sensor disagrees. The interesting question is not “can I retrieve all four records?” It is whether the combined temporal evidence is sufficient to establish an overheating event.

WHERE MOOLBASE FITS

It is not trying to make every other AI database obsolete.

Different systems answer different questions. MoolBase focuses on the evidence process that turns evolving observations into a revisable current fact state.

System focusPrimary question
Vector / semantic databaseWhat stored information is most similar to this query?
Knowledge graphWhat entities and relationships are represented?
Event storeWhat happened, and in what order?
Agent memoryWhat should this agent retain and retrieve later?
MoolBaseGiven changing evidence, what fact is currently established — and why?

MoolBase can complement these systems. It is a temporal epistemic layer, not a claim that similarity search, graph traversal or event storage are unnecessary.

UNDER THE HOOD

A persistent loop from evidence to an established, revisable fact.

The implementation separates storage, evidence topology, competing hypotheses, dialectical challenge and inspectable receipts so each stage can remain explicit.

01

Temporal evidence

Observations arrive with provenance, lifecycle and changing context.

02

MoolBase Core

Durable C++20 evidence, causal-memory and versioned state.

03

Dense hexagonal lattice

Durable axial topology, validated bonds and optional lattice-aware retrieval.

04

FiberBundle

Projects evidence paths while preserving target, role, lineage and independence.

05

HypoKosh

Maintains competing possible facts and governs convergence or abstention.

06

DWM

Challenges the leader through opposition, reopen and bounded re-expansion.

07

Re-convergence

Updated evidence returns to the process until the configured policy can settle.

08

Epistemic receipt

Preserves what was established, what opposed it and why the state changed.

Important boundary: “established” means established under the configured evidence policy and available evidence. MoolBase does not claim objective or semantic truth.

WHERE THIS COULD GO

This is a research direction, not a capability claim for the current developer preview.

Run your first application

Download and extract the DB and examples ZIPs in the same directory. With C++20, CMake and Python 3:

export MOOLBASE_PREFIX="$PWD/moolbase-0.6.0-alpha.2-linux-x86_64"
cd moolbase-0.6.0-alpha.2-examples
cmake -S . -B build-showcase -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$MOOLBASE_PREFIX"
cmake --build build-showcase -j2
python3 examples/customer_showcase/python_memory.py
python3 examples/customer_showcase/python_http.py \
  --server "$MOOLBASE_PREFIX/bin/graphenedb_server"

Memory correction: EU resolved → no operative answer → US resolved. The HTTP example also checks persisted evidence after restarting the server. Fixtures are synthetic; these are not customer case studies.
