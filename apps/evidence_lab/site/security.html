SECURITY BOUNDARY — DEVELOPER ALPHA

Every public run is bounded and isolated

The public gateway never exposes the GrapheneDB pilot server directly. It validates the request and dispatches one disposable worker for the run.

Upload controls

Extension and signature checks, archive traversal and symlink rejection, nested-archive and expansion limits, credential-pattern scanning and malware scanning before parsing.

Worker isolation

One Kubernetes Job per run, no worker service-account token, deny-all worker networking, non-root execution, read-only root filesystem and dropped Linux capabilities.

Resource controls

Bounded input size, graph size, query count, CPU, memory, ephemeral storage, recursion and wall-clock execution.

Session controls

Random anonymous session identifiers, cross-session access checks, private artifacts, automatic expiry and immediate deletion.

Gateway controls

TLS termination, host and origin allowlists, request-size limits, rate limits, request identifiers, no-store responses and restricted Kubernetes job permissions.

Evidence

Live runs expose the exact GrapheneDB commit, dataset hash, worker image reference, execution events and a checksum-protected reproduction bundle.

Not certified for

Enterprise multi-tenancy, regulated workloads, confidential source code, production decision authority, internet-edge GrapheneDB administration or semantic-truth guarantees.
